# 隐私保护说明

## 本次发布范围

仅包含通用 Skill、文本规则、合成数据测试、Python 辅助工具及简单 SVG 图标。发布准备目录从文件白名单独立复制，没有导入原工作目录或历史 Git 仓库。

不包含简历、真实姓名、个人手机号、微信、个人邮箱、个人电脑路径、生日、学校/雇主介绍、客户资料、运营业绩表、参考视频、人像、生成素材、前端、桥接运行目录或 API 凭据。

## 私有仓库并非完全匿名

初次发布应设为 **Private**，公开前再次人工审核。仓库所有者、授权协作者和 GitHub 仍可访问私有仓库。转为公开后，GitHub 用户名、已有头像/简介及公开活动可能把仓库关联到个人。

提交必须采用仓库局部配置或单次命令指定的非实名身份和隐私邮箱；不要修改全局 Git 配置，也不要沿用源目录历史。公开前检查全部提交的作者、提交者、邮箱、说明、标签及发布附件。文件检查通过不等于整个 GitHub 账号已经匿名。

## 真实项目放在哪里

将项目工作目录放在仓库外。`project.json`、参考素材、版本图、蒙版、质检报告和错误日志都可能含敏感信息：

- 本地绝对路径可能暴露系统用户名、单位目录和项目名称。
- `actor`、备注、参考 URL 和历史记录可能含真实姓名或商业信息；建议用 `creator`、`reviewer`、`user` 等角色标识。
- 清单中的 SHA-256 不会隐藏文件名、备注或路径，也不是匿名化机制。
- 旧版迁移会保留 `legacy_snapshot`，可能保留原清单中的敏感数据。
- preflight、抽帧及异常输出可能打印本地工具或文件路径；不要直接复制到公开 Issue。
- 合成测试会在系统临时目录创建测试文件；这些临时文件不属于发布内容。

`.gitignore` 是防误操作护栏，不是安全边界：`git add -f`、更改后缀或上传附件仍可能绕过它。不要把密钥交给 Skill 或写进提示词。它不自带账号隔离、自动打码、访问控制或零留存模型服务。

## 公开前检查清单

1. 确认仓库仍为私有，协作者范围正确。
2. 查看 `git ls-files`：只能有说明文档、Skill 源文件和合成测试。
3. 检查所有提交的 `git log --format=fuller`，确认无真实姓名、个人邮箱和敏感说明。
4. 扫描姓名、联系方式、个人路径、密钥、凭据、客户/公司资料，并人工检查二进制和 SVG 内容。
5. 检查 Issue、讨论、Release、Actions 日志和附件；发布扫描只覆盖准备的代码文件，不能替代平台全站检查。
6. 确定许可证及示例素材使用权后，再由所有者主动转为公开。

如果发现密钥泄露，先吊销/轮换密钥；仅删除文件或改回私有并不能保证消除外部副本。涉及历史清理或删除时，应另行确认范围并保留可恢复备份。

## 使用素材的边界

只处理拥有使用权或明确授权的参考视频、产品图和人像。人物真实性审核用于提升内容质量，不应用于冒充真实身份、伪造背书或隐瞒依法必须披露的信息。是否上传素材到模型服务、服务的留存与训练政策，由实际执行环境决定，使用前应自行确认。
