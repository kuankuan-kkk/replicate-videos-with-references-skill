# Errors, Conflicts, and Recovery

Use the narrowest safe recovery and preserve valid completed work.

| Condition | Action |
| --- | --- |
| Only cover/still available | Stop source-dependent sequencing; request the complete video |
| Video inaccessible or undecodable | Name the file and failure; request a usable export or link/file access |
| Character face unclear | Block only frames requiring face replacement |
| Full-body identity missing | Request it only if full-body identity traits must be exact |
| Exact product evidence incomplete | Block only mapped product frames and list the required view/state |
| No explicit mask editor | Downgrade to level B only with disclosure/acceptance; otherwise deliver mask plan |
| One fusion source has no unique usable contribution | Report before generation and request permission to omit or replace it |
| Face, hand, reflection, or product fails QA | Use approved main/associated union region. Count attempts per B+issue across versions. Stop after two distinct failed repairs; only a recorded human-reviewed new plan starts a new epoch, without erasing history |
| User corrections conflict | Apply the latest explicit correction if priority is clear; otherwise ask one focused choice |
| “Everything else unchanged” conflicts with new camera/room/action | Explain the exact incompatible locks and ask which one has priority |
| Required fidelity is impossible | State the failed invariant, capability level, and closest honest deliverable; never substitute silently |

Retries do not expand authorization. Never browse for products, invent missing brand truth, introduce new people, or alter unrelated regions as a workaround.

When resuming, validate the manifest first. Continue from the last passing state rather than repeating completed analysis or regenerating accepted frames.

Changed or missing files, stale approvals and conflicting camera/aspect/duration must block delivery. Do not repair approval by setting a boolean. Revocation returns the task to revalidation and retains older outputs; use the state helper. A locked-region pixel failure requires baseline restoration or rollback rather than wider authorization. A generation restart, browser refresh or new output version never resets an unresolved issue's retry history.
